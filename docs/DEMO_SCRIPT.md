# CiteCheck 课堂演示顺序

演示前确认 `.env` 里有 `LLM_API_KEY`，并已执行 `cd frontend && npm run build`。启动：

```bash
python -m citecheck.web
```

打开 http://127.0.0.1:8000 。下面按约 8 分钟安排。

## 1. 登录（30 秒）

注册或登录。左侧是工作区导航，语言在右上角切换。

## 2. 文献（1 分钟）

在概览或文献库点「导入示例论文」。两篇示例会在后台解析，状态从「解析中」变成「可阅读」。也可以另传一篇自己的 PDF，单文件不超过 20MB。

## 3. AI 阅读器（4 分钟）

打开 WidgetNet。三栏分别是目录、PDF、对话。

建议问题：

> What accuracy does WidgetNet reach on Widget-100?

模式保持 **Full**。回答出来后说明三件事：

- 顶部标签是 Full，轨迹里先检索再停止。
- 正式答案只保留有原文支撑的句子，每句后面是页码。
- 点页码，PDF 跳到对应页。示例论文能精确高亮句子；匹配不到时会标明「页级定位」，只跳页、不高亮错误段落。

展开「逐句核对」，不确定的句子留在详情里，不进正式答案。

在 PDF 里选中一句，用浮动菜单做「解释」或「翻译成中文」。这一步只调用一次模型，不跑完整 Agent。

## 4. 评测实验室（2 分钟）

打开评测实验室，选择 `data/results/latest.json`。页面上的数字就是这个文件里的数字。

当前这份自建题结果里，Full CiteCheck 的引用精确率是 87.0%，证据召回是 100%，不确定句比例是 10.0%。Token F1 是 41.0%，低于不做逐句核对的 B3，因为核对会删掉没有原文支撑的句子。文件里有 24 次调用失败（网络超时），这些行不计入均值，页面上有提示。

对比顺序：B1 不读论文，B2 只检索一次，B3 加上规划，Full 再逐句核对。消融是去掉规划、只用向量检索、去掉核对。

## 5. 收尾（30 秒）

研究记录里可以回到刚才的对话。设置页能看到当前是本地存储还是腾讯云 COS，以及模型密钥是否已配置。密钥本身不显示。

旧版单页在 `/legacy`，同一套问答接口仍可用。

## 不要在课堂上做的事

- 不要现场跑完整评测，一次 custom 评测要调用很多次模型。
- 不要把 `.env` 或 COS 密钥投到屏幕上。
